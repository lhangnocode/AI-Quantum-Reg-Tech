# Investor demo status

## Demo path

1. Open `/stocks`; browse the 9-ticker universe (VNM, MCH, MCM, SBT, QNS, KDC, PAN, IDP, SAB) from `data/QuantumRegTech_Input_Data_final.xlsx`. Profile screens show the latest data year (2024 → forecast 2025).
2. Open `/portfolio`, pick a data set year (2021–2024) and 3–9 tickers. The page calculates an automatic allocation from the selected objective. The Markowitz + ESG panel uses γ/δ, CAPM, ESGi, RFin and monthly-price covariance to produce a classical SLSQP recommendation with 2%–40% bounds; users can apply it or return to automatic weights. Historical return comparisons are kept in the research report, separate from the live allocation view.
3. In “Theo dõi sự kiện xử phạt”, select one ticker and a 6/12/24/36/60-month lookback ending today. FastAPI starts one Firecrawl Agent job for that date range (background job, browser polls). Events already reviewed in the workbook (`OSINT_Events`, `Include = 1`) are shown as reviewed and already counted. Each new agent event must be opened and accepted with a level 1–3 (or rejected) by the user; P_OSINT = Params table of the highest level (no summing), R_fin,total updates in the browser session. Source re-reading (`OSINT_VERIFY_SOURCES`) and Jina are off by default, so agent quotes are shown as “chưa đối chiếu trang nguồn”. Without a Firecrawl key or when FastAPI is down, only reviewed workbook events appear.
4. Open `/private`, add up to ten documents, and process them sequentially. PDF text extraction/OCR and Rules baseline run in the browser. With a separate consent checkbox, extracted text can run through the LangGraph/LangChain Document Agent; page/quote/value grounding is required before AI values enter Z′. Results can be printed.

## Deep-demo API foundation

- A separate FastAPI service under `backend/` serves a searchable, cursor-paginated universe from generated workbook JSON and returns data-version/provenance/status metadata.
- FastAPI has been reorganized into a composition root with versioned API routers, domain contracts, workbook and universe repositories, service adapters, and LangGraph agents; existing API paths are preserved.
- New tickers can be registered with a source reference. They are stored in local SQLite as `pending_data` and list required fields still missing; registration does not fabricate metrics.
- Tickers registered through `/stocks` stay `pending_data` until their raw rows exist in the workbook; the build never invents metrics.
- Implemented routes include `/health`, Neo4j readiness, paginated company/universe reads, company Z-score/ESG/OSINT and methodology reads, `GET /api/v1/financial-engine`, ticker registration, assessment, `POST /api/v1/osint/scans`, and opt-in `POST /api/v1/private/extract`.
- `.env.local` is configured with `NEXT_PUBLIC_USE_MOCK=false` and the local FastAPI URL. The original company lookup page remains available at `/company/VNM`; public data reads go through FastAPI. PDF processing stays in-browser.
- OSINT was manually exercised through `POST /api/osint/scan` in Next.js: response `200`, LangGraph `discover → graph_enrichment → extract → classify → validate`, and connected Neo4j adapter. Live-provider run returned 9 candidates and Groq structured proposals; proposal and exact-quote counts vary. Provider requests can return no articles, in which case the model is correctly skipped. The database has no nodes, so graph matching returns empty. Candidates remain for review; these are point-in-time checks, not a reliability guarantee.
- `/stocks` now submits new tickers through a same-origin Next.js API proxy to the FastAPI registry and shows registered symbols as `pending_data`; pending symbols cannot be selected into the optimizer or opened as scored profiles until source data is imported and validated.
- Run instructions and configuration are in [demo runbook](DEMO_RUNBOOK.md), [backend README](../backend/README.md), [.env.example](../.env.example) (frontend), [backend/.env.example](../backend/.env.example) (FastAPI) and the [deploy checklist](DEPLOY.md). Generate JSON first with `npm run data`, then run FastAPI and Next.js.

## Accurate demo claims

- `scripts/build-financial-engine-data.mjs` recalculates all 36 company-years (X1–X5, Altman Z/zone, R_fin, P_OSINT, CAPM, realized return, ESG peer percentile) from the workbook's raw `GOC_*` sheets and reconciles them with `TINH_TONG_HOP` / `ESG_Scores`; any mismatch fails the build. Data is historical, not a live feed.
- The portfolio page offers automatic weights and a separate classical Markowitz + ESG recommendation. Its 36-month monthly-price covariance and 2%–40% bounds follow the Kaggle notebook; γ and δ are adjustable. The historical comparison is documented in [the evaluation report](Bao_cao_danh_gia_Markowitz_ESG.docx), including the PAN 2023/KDC 2024 price-series discrepancies. This is not QUBO/QAOA or an out-of-sample performance claim. The old Baseline / ESG-aware workbook scenarios and the Cổng 2 sample (TH) were removed with the 4-ticker workbook.
- Firecrawl Agent is the only OSINT discovery source. Its output is a candidate until the user accepts it; it must not be described as a confirmed violation. Acceptance is session-only (no store, no audit log).
- Neo4j Aura is connected through the backend's read-only Python adapter. The graph is empty until an operator deliberately runs the write-gated workbook demo seed. Aura hosted MCP is separately configured for an MCP-compatible IDE with browser OAuth; the app backend does not use Aura API client secrets.
- OSINT is capped at four tickers per request and three running scans. Each scan costs up to `OSINT_AGENT_MAX_CREDITS` (default 500) per ticker and usually takes minutes. Jobs live in API process memory (single worker, lost on restart). The agent flow has not yet been verified end-to-end with a real key in this version.
- PDF text/OCR and rule parser run in the browser. With separate user opt-in, extracted text is sent to the configured LLM; a LangGraph extraction/quote-validation workflow maps fields without requiring one exact layout. Values without page/quote evidence are rejected and rule-parser values remain the comparison baseline. The original PDF is not sent. There is no RAG, cross-document conflict resolution, persistent field approval workflow, or persistence of private findings.
- The document request is bounded and selects finance-relevant lines to reduce provider context errors. A provider may still reject requests or hit quota; in that case results remain on Rules baseline and UI reports the agent unavailable.
- The browser drops its references to uploaded files after processing. This does not establish deletion from browser memory, logs, caches, or external infrastructure; do not call it a system-wide Zero-Retention guarantee.
- Adding a ticker to the universe requires complete sourced input data; an arbitrary ticker string does not create financial/ESG metrics.

Live OSINT requires `FIRECRAWL_API_KEY`; without it only reviewed workbook events are shown. LLM level suggestions run only with `OSINT_VERIFY_SOURCES=true` plus `AI_PROVIDER=groq|gemini` and the matching key. `JINA_API_KEY` is unused. These are backend variables: copy missing names from `backend/.env.example` into `backend/.env` (or the backend host's secret manager), preserve existing keys, then restart FastAPI. Keep keys server-side; do not use `NEXT_PUBLIC_` names for them. Public article excerpts will be sent to the configured LLM provider; do not use this flow for confidential/private document text.
